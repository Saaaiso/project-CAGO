# Frontend — инструкция для участника команды

Привет! Ты отвечаешь за Frontend — интерфейс CAGO.

## Что уже есть

В репозитории подготовлен API-контракт `docs/openapi.yaml`. Самого Frontend-приложения пока нет: папка `frontend` ещё пустая. Поэтому команд запуска, сборки и тестирования пока тоже нет.

## Как начать

Склонируй репозиторий и посмотри API-контракт в `docs/openapi.yaml`. Согласуй с Backend-разработчиком адрес API и изменения контракта.

Для разработки интерфейса PostgreSQL, Redis и MinIO не нужны. Frontend работает с Backend через API — не подключай браузер напрямую к базам или MinIO. Пароли из `.env` тебе не нужны; не проси и не пересылай их.

Когда приложение появится, добавь сюда команды его установки, запуска и тестирования, а также адрес Backend API.

# CAGO Web (Central Asia Green Orbit)

Фронтенд мониторинга полей: React + TypeScript + Vite + Leaflet.
Бэкенд (C#), Redis, Postgres, MinIO и Python-воркеры живут отдельно; фронт общается с ними только через `/api/*`.

## Запуск

```bash
npm install
cp .env.example .env     # VITE_USE_MOCK=true — работаем на моках
npm run dev              # http://localhost:5173
npm run build            # проверка типов + prod-сборка
```

## Разделы

## Языки (EN / RU / КЫ)

Переключатель в шапке (на телефоне — в верхней панели) и в Настройки → Профиль фермы → Language. Выбор сохраняется в `localStorage`; при первом входе язык берётся из браузера.

- Ключ перевода — английский текст: `t('Add field')`. Для `en` он возвращается как есть, для `ru`/`ky` берётся из `src/i18n/ru.ts` и `src/i18n/ky.ts`.
- `t()` — тексты интерфейса, `td()` — демо/пользовательские данные (названия полей, рекомендации); без перевода `td()` молча вернёт оригинал.
- Подстановки: `t('{n} fields', { n: 6 })`.
- Даты и числа форматируются по языку (`fmtDay`, `fmtDateTime` в `src/i18n`); для кыргызского даты форматируются вручную.
- Новый текст: оберните в `t('…')` и добавьте пару в `ru.ts` и `ky.ts`. В dev-режиме (`npm run dev`) пропущенные переводы пишутся в консоль браузера: `[i18n:ru] нет перевода: "…"`.
- Смена языка перемонтирует страницы (состояние фермы и выбранного поля сохраняется).
- Реальные данные с бэкенда (названия, тексты рекомендаций) должен локализовать сам бэкенд; `td()` нужен только для демо-данных.

Адаптив: ≥1024 sidebar, 640–1023 узкая панель иконок, <640 нижняя навигация + экран More.

## Структура

```
src/
  api/        client.ts (http, USE_MOCK), services.ts (все запросы), imagery.ts (конвейер снимков)
  state/      FarmContext — ферма, поля, алерты, выбранное поле (общее для страниц)
  hooks/      useAsync
  mocks/      data.ts — демо-данные (вокруг Алматы)
  components/ FieldMap (Leaflet), Ui (Card, Modal, графики), AddFieldModal, Toast, Icon
  layout/     AppLayout, nav.ts
  pages/      по одному файлу на раздел
  types.ts    доменные типы
  i18n/       index.tsx (t, td, провайдер, даты), ru.ts, ky.ts
  utils.ts    цвета слоёв, площадь полигона, CSV
```

## Подключение к бэкенду

1. Все пути в `src/api/services.ts` (`PATHS`) и `src/api/imagery.ts` — подставить из контрактов.
2. Если форма ответа отличается от `src/types.ts` — маппить в `services.ts`, страницы не трогать.
3. `.env`: `VITE_USE_MOCK=false`, `VITE_API_TARGET=http://<backend>`. Vite проксирует `/api` (CORS не нужен); в проде это делает Nginx.
4. Статусы снимков (`DONE`/`FAILED`) — в `imagery.ts`.

## Известные упрощения

- Нет авторизации (ждём контракт).
- Глубина почвы и часть графиков (Reports) считаются на моках.
- Карта: OSM / Esri World Imagery (для тайлов нужен интернет).
- Генерация отчётов, добавление устройств и участников — заглушки с уведомлением.
