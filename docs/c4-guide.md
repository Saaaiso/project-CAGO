# Как читать C4-диаграммы

C4 показывает устройство программы с разных расстояний. Первая схема — общий вид, следующие постепенно раскрывают детали. Это не схема таблиц БД. Диаграммы описывают согласованную архитектуру MVP; наличие компонента на схеме само по себе не означает, что он уже развёрнут.

Чтобы увидеть таблицы и связи между ними, открой [ER-диаграмму](./diagrams/database.md). Подробное описание таблиц находится в [`/db/schema.md`](../db/schema.md).

## 1. Контекст: кто и с чем работает

Открой [контекстную диаграмму](./diagrams/c4.md#контекст-системы).

Внешний круг показывает людей и сторонние системы:

- Специалист айыл окмоту ведёт земельные участки и декларации.
- Пастбищный комитет ведёт планы пастбищ и поголовье.
- Районные органы и министерство смотрят отчёты и аналитику.
- Администратор управляет пользователями и справочниками.
- Спутниковые данные, кадастр, провайдер входа и почтовые сервисы находятся вне нашей системы.

Стрелка показывает направление взаимодействия. Например, система получает спутниковые снимки и отправляет уведомления.

## 2. Части системы: где выполняется работа

Открой диаграмму [«Части системы»](./diagrams/c4.md#части-системы).

- **Веб-приложение** отображается в браузере. Пользователь нажимает кнопки и видит карту.
- **Веб-сервер** принимает HTTPS-запросы и передаёт их Backend.
- **Backend** проверяет пользователя и его права, затем читает или изменяет записи в PostgreSQL.
- **Worker** выполняет долгие задачи отдельно от пользовательского запроса. Например, импортирует большой файл или рассчитывает NDVI.
- **PostgreSQL + PostGIS** хранят таблицы и геометрию участков.
- **Redis** передаёт задания между Backend и Worker, а также хранит кэш.
- **MinIO** хранит сами документы и растры. В PostgreSQL остаются их имена и ключи хранения.

### Пример фонового задания

1. Backend в одной транзакции записывает задание в `platform.job` и событие в `platform.outbox`; publisher отправляет событие в Redis Stream `cago:jobs`.
2. Worker получает сообщение из consumer group и читает параметры задания из PostgreSQL, а нужную геометрию — из `land`.
3. Worker обрабатывает снимок и сохраняет результат в `monitoring`.
4. Worker сохраняет результат и состояние задания в `platform.job`, затем подтверждает сообщение в Redis.
5. Backend показывает пользователю результат.

Worker не должен напрямую менять земельные участки или права на них. Его доступ к БД ограничен ролью `worker_rw`; детали приведены в [`db/usage.md`](../db/usage.md).

## 3. Модули Backend: кто отвечает за данные

Открой диаграмму [«Модули Backend»](./diagrams/c4.md#модули-backend).

- **IAM / Доступ** проверяет, кто вошёл и какие действия ему разрешены.
- **Org / Территории** хранит административное дерево и организации.
- **Land / Земли** отвечает за участки, правообладателей и историю изменений.
- **Pasture / Пастбища** отвечает за пастбищные территории, поголовье и планы.
- **Crop / Посевы** хранит сезоны и сведения о культурах на участках.
- **Monitoring / Мониторинг** хранит спутниковые наблюдения и оповещения.
- **Docs / Документы** хранит сведения о файлах; сами файлы находятся в MinIO.
- **Reports / Отчёты** собирает сводные данные и готовит выгрузки.
- **Platform / Общие функции** содержит очередь фоновых задач, события и аудит.

Например, при создании декларации модуль посевов связывает её с участком из `land` и сезоном из `crop`. Пользователь не должен самостоятельно выбирать территорию доступа: Backend проверяет её по назначениям в IAM.

## Термины на диаграммах

| Термин | Простое объяснение |
|---|---|
| SPA | Веб-приложение, которое загружается в браузер и обновляет экран без полной перезагрузки страницы. |
| REST API | Набор HTTP-запросов, через которые веб-приложение обращается к Backend. |
| Reverse proxy | Веб-сервер, который принимает запросы и направляет их нужному сервису. WAF добавляет фильтрацию подозрительных запросов. |
| MVT | Формат векторных тайлов карты; позволяет загружать геоданные частями для нужного масштаба. |
| OIDC / IdP | Стандарт и внешний сервис для проверки личности при входе. |
| Redis Streams | Очередь сообщений в Redis. Backend публикует задание, Worker забирает его и подтверждает обработку. |
| NDVI | Индекс по спутниковым снимкам, который помогает оценивать состояние растительности. |
| STAC | Каталог, через который находят спутниковые снимки и их метаданные. |
| COG | Геопривязанный растровый файл, который можно читать частями, не скачивая весь снимок. |
| Outbox | Таблица `platform.outbox`, где Backend сохраняет событие в той же БД-транзакции, что и изменение данных. Отдельный обработчик позже отправляет событие в очередь. |
| Pre-signed URL | Временная ссылка, разрешающая загрузить или скачать объект из MinIO без передачи пароля от хранилища. |

## Чем C4 отличается от ER

- **C4** показывает программу: пользователей, сервисы и обмен между ними.
- **ER** показывает данные: таблицы, их поля и связи.

Если вопрос «какой сервис обрабатывает импорт?» — смотри C4. Если вопрос «где хранится площадь участка?» — смотри [`db/schema.md`](../db/schema.md) и ER-диаграмму.
