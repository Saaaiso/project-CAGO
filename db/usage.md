# Как Backend и Worker работают с БД

Короткая инструкция для разработчиков Backend и Worker. Полное описание таблиц и ограничений — в [`schema.md`](./schema.md). Миграции и SQL — в [`migrations/`](./migrations/).

## Сначала: две разные системы ролей

У Backend и Worker есть роли PostgreSQL, которые определяют, что сервису разрешено делать в базе:

- `app_rw` — группа прав Backend;
- `worker_rw` — группа прав Worker;
- `report_ro` — группа только для чтения отчётов.

Это **не** то же самое, что `iam.role`. Таблица `iam.role` хранит бизнес-роли пользователей приложения, например специалиста или администратора. Роли PostgreSQL определяют права самого подключения к базе.

Миграция 016 создаёт группы, но не создаёт логины и пароли. В текущем окружении назначьте логины группам так:

```sql
GRANT app_rw TO back_aidar;
GRANT worker_rw TO worker_max;
```

Для другого окружения замените имена логинов на те, которые созданы там. Не записывайте пароли в этот файл, миграции или репозиторий. `dba_admin` используйте для настройки БД и запуска миграций, не для запуска Backend или Worker.

## Backend

Backend подключается под логином, которому выдана роль `app_rw`. Он обслуживает пользовательские запросы, проверяет бизнес-права и записывает основные данные.

| Схема | Что делает Backend |
|---|---|
| `org` | Читает и меняет административные территории и организации. |
| `iam` | Читает и меняет учётные записи, бизнес-роли и их территориальные назначения. |
| `land` | Ведёт земельные участки, субъектов, права и историю участков. |
| `pasture` | Ведёт пастбища, поголовье, планы и строки планов. |
| `crop` | Ведёт сезоны и декларации посевов. |
| `monitoring` | Читает и меняет спутниковые сцены, наблюдения и оповещения. |
| `docs` | Сохраняет сведения о файлах и связь документа с участком. Сам файл хранится отдельно в MinIO. |
| `platform` | Создаёт фоновые задания, пакеты импорта и записи outbox. |
| `ref` | Только читает справочники категорий земель, культур, видов прав, скота и документов. |
| `audit` | Только добавляет строки в журнал значимых действий. |

Обычный путь запроса: Backend проверяет пользователя и его бизнес-роль, проверяет доступ к территории, затем читает или меняет нужные таблицы. PostgreSQL-роль `app_rw` сама по себе не ограничивает пользователя конкретным районом: это проверяет Backend. Row-Level Security (RLS) пока не настроен.

## Worker

Worker подключается под логином с ролью `worker_rw`. Он выполняет долгие задачи: импорт, обработку спутниковых снимков и другие фоновые операции.

| Схема | Доступ Worker | Для чего |
|---|---|---|
| `land` | Только SELECT | Читает данные участков для расчётов. |
| `monitoring` | SELECT, INSERT, UPDATE | Сохраняет сцены, результаты наблюдений и оповещения. |
| `platform` | SELECT, INSERT, UPDATE | Читает и обновляет задания, а также сохраняет результаты импорта и события outbox. |

Worker не получает доступ к `iam`, `org`, `ref`, `pasture`, `crop`, `docs` и `audit`. Он не может менять или удалять строки в `land`. Текущий GRANT на `land` разрешает читать все существующие таблицы этой схемы, не только `land.parcel`; не передавайте Worker лишние персональные данные в запросах.

Пример обработки снимка:

1. Worker получает задание через Redis.
2. Читает геометрию участка из `land`.
3. Берёт или сохраняет файл в MinIO.
4. Записывает результат в `monitoring`.
5. Обновляет состояние задания в `platform`.

Для доступа к ключу файла Worker может использовать данные задания. Прямого доступа Worker к `docs.file_object` сейчас нет. Если обработчику понадобится читать эту таблицу, выдайте отдельное минимальное право новой миграцией — не подключайте Worker под `app_rw`.

## Правила для обоих сервисов

- Схему БД меняйте новой SQL-миграцией. Не редактируйте миграцию, которая уже была применена.
- Миграции выполняет отдельный привилегированный шаг до запуска Backend и Worker. Сервисы не должны создавать таблицы или работать под DBA.
- `land.parcel.area_ha` и `pasture.pasture_unit.area_ha` вычисляет триггер PostgreSQL из геометрии. `crop.crop_declaration.area_ha` — заявленная площадь, которую БД проверяет относительно участка.
- Справочники в `ref` меняются при настройке окружения, а не обычным подключением Backend.
- Миграция 016 выдаёт права на существующие на тот момент таблицы. Если будущая миграция добавляет таблицу, проверьте и явно добавьте нужные GRANT-ы.
- Права на уровне таблиц не заменяют проверки бизнес-прав и территориального доступа.
